# 评分工作台与负责人评分入口

本文说明评分工作台与负责人评分界面。代码推送与每次生产部署继续遵守根目录 `AGENTS.md`，实际发布状态以发布验证记录为准。

## 页面与入口

导航和页头统一使用“评分工作台”，保留原 `scores` 路由及既有结果、配评链接。管理页提供“负责人评分、得分结果、月度配评”三个页签。老板首次直接进入评分工作台时默认负责人评分；显式指定结果、配评或员工详情的链接继续打开指定页面。

评分工作台中的负责人评分默认上一个完整月份，也可以通过统一的月份选择器查看其他月份。原部门管理入口保留默认当前月份的行为。老板对部门负责人的评分使用既有部门评分接口；负责人给普通下属评分继续保留原流程，两者不混淆。

## 评分操作

- 按部门列出负责人，区分待评分、已完成、待处理和无需评分，并支持按姓名或部门搜索。
- 未设置负责人时明确显示“负责人未设置”；只有已有负责人身份但缺少姓名时才显示“姓名待同步”。老板角色按既有规则无需接受老板评分，单列“无需评分”，不计入配置问题；在职月份、身份同步和已锁定评分关系分别显示具体原因。
- 左侧选择对象，右侧填写 0～100 分及必填评价；0 分是有效分数。
- “提交评分”保存并展示锁定结果；“提交并评下一位”只在保存成功后进入下一位。
- 保存失败保留当前对象和输入；月份、部门和负责人共同标识草稿，切换月份不会将另一月份的草稿带入提交。
- 保存期间锁定相关月份及操作，旧请求不能覆盖当前月份或负责人。
- 老板可提交评分；管理员按原权限查看，普通员工不能通过管理界面给部门负责人评分。

一名负责人兼任多个部门时，各部门仍分别评分，不将多项评分合成一次提交。老板部分按原规则汇总，占月度综合分30%，同事互评占70%；两部分完成后自动发布。历史负责人、月度冻结范围及已移除部门历史继续保留。

部门管理中的负责人评分入口复用同一组件，避免两套表单的月份、草稿和锁定行为不同。此变更不修改周报AI评分标准、重评状态或人工评分数据。

## 本地验证

验证老板直接进入、历史深链接、管理端只读、重复负责人按部门分开、有效0分、失败保留输入、成功后下一位、月份隔离、旧响应保护、历史锁定，以及桌面和390px移动端布局。所有评分提交均使用隔离测试或模拟接口，不发送真实评分或提醒。

专项命令：`npm run test:boss-scoring`。已加入 `npm run test:business` 完整回归。测试默认构建到新的保留目录，也支持通过 `TEST_STATIC_DIR` 复用本地构建，不清空已有文件。
