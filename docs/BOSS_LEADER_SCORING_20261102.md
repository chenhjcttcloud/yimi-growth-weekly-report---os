# 评分工作台与负责人评分入口

本文说明评分工作台与负责人评分界面。代码推送与每次生产部署继续遵守根目录 `AGENTS.md`，实际发布状态以发布验证记录为准。

## 页面与入口

导航和页头统一使用“评分工作台”，保留原 `scores` 路由及既有结果、配评链接。管理页提供“负责人评分、得分结果、月度配评”三个页签。老板首次直接进入评分工作台时默认负责人评分；显式指定结果、配评或员工详情的链接继续打开指定页面。

评分工作台中的负责人评分默认上一个完整月份，也可以通过统一的月份选择器查看其他月份。原部门管理评分链接会转到评分工作台，保留链接中的月份。老板在此给部门负责人评分，负责人给普通下属评分沿用原流程。

## 评分操作

- 每位负责人每月一张卡片、一个评分任务。卡片展示所负责的部门，支持按姓名或部门搜索。进度按人员统计，缺少负责人的部门仍可在待处理列表查看。
- 未设置负责人时明确显示“负责人未设置”；只有已有负责人身份但缺少姓名时才显示“姓名待同步”。老板角色按既有规则无需接受老板评分，单列“无需评分”，不计入配置问题；在职月份、身份同步和已锁定评分关系分别显示具体原因。
- 左侧选择对象，右侧填写 0～100 分及必填评价；0 分是有效分数。
- “提交评分”保存并展示锁定结果。“提交并评下一位”在保存成功后进入下一位待评负责人。
- 保存失败保留当前对象和输入。草稿按月份和负责人保存。旧的按部门草稿留在原浏览器存储里，人员评分表单从空白开始。
- 保存期间锁定相关月份及操作，旧请求不能覆盖当前月份或负责人。
- 老板可提交评分；管理员按原权限查看，普通员工不能通过管理界面给部门负责人评分。

一名负责人兼任多个部门时，老板提交一次个人总评，占月度综合分的 30%，同事互评占 70%。两部分完成后自动发布。已发布的结果和按旧规则评完的部门评分继续沿用原分。旧规则只评过部分部门时，可提交一次个人总评。新总评计入当月综合分，原部门评分可在历史中查看。

## 本地验证

验证老板直接进入、历史深链接、管理端只读、兼任多部门只评一次、同名人员分卡、有效 0 分、失败保留输入、成功后进入下一人、月份隔离、旧响应保护、历史锁定，以及桌面和 390px 移动端布局。所有评分提交均使用隔离测试或模拟接口，不发送真实评分或提醒。

专项命令：`npm run test:boss-scoring`。已加入 `npm run test:business` 完整回归。测试默认构建到新的保留目录，也支持通过 `TEST_STATIC_DIR` 复用本地构建，不清空已有文件。
