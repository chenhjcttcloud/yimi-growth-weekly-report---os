# 全系统专项修复

本轮按已复现的六项问题修复，只在本地开发、构建和测试，不自动部署生产或推送仓库。

## 评分与提醒

- 手动停用评分人或被评分人时，已开始评分或已冻结月份继续保留原应评分人数；同月多个周期、负责人/老板评分、旧版评分和已发布结果均受保护。未使用的关系可以停用，恢复账号不自动重开旧关系。未完成月份不能因为停用而提前发布最终分。
- SQLite 提交时间按 UTC 解析，保留 ISO 时区偏移。最终结果尚未发布时，同事互评的四小时修改窗口在 UTC 和上海时区一致；已发布结果仍保持锁定。工作日判断按日历日期计算，不依赖服务器时区。
- 提醒预览不创建评分周期，不自动复制上月关系。没有准备好周期时给出手动配评提示；真实提醒请求不能绕过周期准备流程。未指定或不存在的周期不会自动落到另一个月份。

## 页面导航

- 管理看板中的员工入口按 `user_id` 定位，并携带月份和资料页签；缺失或重名不猜测为第一位员工。
- 个人月份、周次跨周报、AI 教练、行动任务和成长轨迹保留；刷新和前后导航恢复对应上下文。切换员工身份时重新校验作用域，不能串用他人的选择。

## 运维记录与配置准备

- 未开启对外通知时，异常仍写入站内告警。使用实际运行时 SQL 适配器测试空收件人、去重和发送行为，避免模拟适配器掩盖数据库约束差异。
- 运维页分别显示容量风险、每日备份开关、故障通知开关、有效收件人和最近备份恢复校验状态。
- 提供只读生产验收脚本、备份告警 JSON 样例和周报提醒环境变量样例。样例不自动应用，且不包含真实人员或凭据。
- 服务器容量不足需扩容或另设备份存储，不能通过删除既有资源处理；生产开关和容量变更仍需当次明确授权。详见 [运维准备](../deploy/OPERATIONS_READINESS.md)。
