1. 选择当前或未来12个月的月份，创建空周期。

3. 展开预览后批量保存，自动排除自评、重复关系。
4. 本月可立即开放，未来月份可预约月初开放。此操作不发送消息。

页面显示待配置人员及已有关系。已评分或已发布的记录锁定，停用关系保留历史。系统不会生成或复制评分人名单，11月仍需管理员手动指定。负责人/老板30%与同事70%的既有评分口径保持一致，全部完成自动发布。

## 回调、会话和真实执行

- 事件配置入口：系统设置 → 飞书与数据集成 → 事件安全与任务创建。未配置凭据时回调关闭；配置 Verification Token 后必须携带匹配值，配置 Encrypt Key 后校验原始请求签名及5分钟时间窗口，重复事件仅处理一次。密钥加密保存、留空保留、不回显。
- 正式认证必须显式配置 SESSION_SECRET。会话默认绝对有效期168小时，可由 SESSION_TTL_HOURS 配置（1—720）；刷新不会无限续期。退出后持久撤销，重启后仍不能重放。
- 上线新会话策略后，旧格式登录会话需要重新登录。不要更换现有 SESSION_SECRET，否则已保存的飞书/AI凭据无法解密。
- “生成公司总结”调用实际模型，保存所属周期和输入指纹；相同内容/模型复用，内容变化标为过期，摘要仍需管理者编辑后显式发送。
- “查看关注任务”打开任务台账。创建需开启集成开关、选择候选并指定在职负责人；只有飞书真实响应成功才记录成功，重复请求复用幂等结果，不再模拟创建。
- 组织部门均分按所选周期统计；没有分析和主题时显示空状态，不混用其他周期的演示结果。运行概览读取持久化的月末提醒配置，区分预约生效和当前启用。

## 服务器本地备份与告警

入口：系统设置 → 备份与告警。自动备份和飞书外发默认关闭；本次本地验证不修改生产设置、不发送真实告警。

- 默认北京时间03:00备份，可修改时间；服务必须运行。重启后当天已错过时间会补做一次，同日任务持久幂等。中断任务标记失败，保留现场，次日继续或管理员手动补做。
- 默认目录是数据库上两级目录下的 `backups/automatic`。生产容器现有挂载对应 `/app/outputs/backups/automatic`，宿主机通常是 `/opt/emie-growth-os/data/backups/automatic`。可用 BACKUP_DIR 指定其他服务器持久目录，不应放在源数据或上传目录内部。
- 快照含SQLite在线一致性备份、APP_DATA_DIR运行文件、上传文件、SHA256清单；数据库与上传文件散列流式计算。目录权限0700、文件0600。SESSION_SECRET和服务器环境文件需运维另外安全保留，不通过页面暴露或打包进业务快照。
- “恢复校验”校验清单、文件散列、运行JSON及SQLite完整性，并在独立 `restore-checks` 目录恢复副本；不覆盖当前数据库或文件。该操作验证可读性及完整性，不代表已执行生产切换，也不验证外部服务在线授权。
- 备份、校验副本和历史记录全部保留，不自动轮转或删除。磁盘不足会显示失败，不能通过自动清理绕过项目禁删规则。日后如需清理，必须由用户针对对象明确变更限制。
- 飞书告警可选最多10名在职接收人，支持“设为当前登录人”；保存接收人不自动开启外发。开启后检查磁盘阈值、备份、周报同步/AI失败和月末消息异常，同问题同日每人一条，发送成功后不重复。临时失败5分钟后重试，第二次失败15分钟后再试，最多3次且限首次发送后40分钟内；重启后沿用原消息UUID继续去重，超过窗口标记待核实。权限等明确拒绝不自动重试。问题解除、关闭外发或停用接收人后停止重试，逐次发送记录保留。外发关闭时只记录问题。开发 mock 环境禁止真实运行告警发送。
- 磁盘告警阈值默认85%，可配置50—99%。阈值只用于告警，不修改数据。自检每分钟执行轻量状态检查，不重复调用AI分析。
- `/health` 实际检查数据库与页面数据可读性，异常返回503；外部飞书或AI故障通过运行状态/告警查看。

告警发送需要飞书 `im:message:send_as_bot` 和接收人处于应用可用范围。生产启用前应先手动创建备份并完成恢复校验，再选择实际告警接收人。

## 月度责任交接与个人催评异常（2026-10-28）

- 新入口：系统设置 → 月度评分交接。列出负责人已停用或身份缺失的未评分任务，管理员选择已有在职负责人并填写说明后交接。交接不发送通知，不改变同事互评名单，不覆盖已提交评分；历史记录追加保存。
- 第一次提交30%评分或人工交接时，冻结该员工当月评分责任计划；之后飞书换部门、换负责人，不会使已提交的30%失效。尚未冻结的未评分计划跟随当前组织资料。已提交评分不可交接；同月其他未提交且负责人不可用的部分可以交接。
- 旧30%评分按保存的原责任快照恢复；新计划、交接历史均不可覆盖或删除。老板评分也在首次提交前保存月度计划；已评分记录保留原被评人；当前负责人变化后，按部门、月份、被评人分别建档，原有已发布结果继续锁定。尚未提交评分的计划跟随飞书当前负责人。
- 被评分人在所选月份未在职时，负责人任务列表不生成任务，评分提交接口和老板部门评分接口都会拒绝录入。历史在职月份仍可查看原记录；在职日期不明确时应先在员工管理核实。
- 已停用评分人不会收到个人催评。待交接状态在管理页面和本人页面明确提示；交接后接任人的等待时间重新计算，达到配置的等待时间后本人才能催评。
- 个人催评收到不明确回执、超时或无法确认成功时，保留原消息标识及“待核实”记录，并计入冷却期；刷新、重启或再次点击都不会立即创建第二条消息。只有明确被服务拒绝、确认没有发送的尝试，才允许修正配置后重试。默认冷却24小时，按所属月份规则配置。
- 回归：`node scripts/test-monthly-handoffs.mjs`；浏览器与接口回归沿用 `scripts/test-hardening-ui.mjs`，覆盖交接权限、交接页面保存、接任人任务、入职前评分拒绝与提醒去重。测试使用匿名数据和拦截响应，不发真实消息。
