# 角色授权页面

日期：2026-10-28。仅本地开发与验证；没有生产部署或仓库推送。

## 入口与交互

老板／管理员进入「系统设置 → 角色与权限」。主页面合并原来的两份全员勾选名单，只展示拥有老板或管理员权限的人员，同一人占一行，角色分别显示。可按角色筛选或搜索姓名、部门、user_id。

- 添加授权：点击右上角「添加授权」，在侧边面板选择角色、搜索并选择在职员工或已同步的飞书负责人，最后点击「确认添加授权」。默认选择管理员，选中人员始终显示在搜索框下方。列表在面板内部滚动。
- 管理授权：点击该人员行的「管理」，单独添加或撤销某一项角色，底部再次确认后保存。普通员工视角无需单独授权。
- 查看、搜索、打开面板、取消或放弃选择均不写入授权；有未保存选择时关闭或切换页面会提示。
- 已有双角色完整保留，添加另一角色不会暗中撤销原角色。双角色仍沿用系统现有的老板视角优先规则。
- 角色说明默认折叠，老板不显示个人成长模块；管理员保留个人分数、周报和评分任务。
- 停用员工和不在当前花名册中的历史授权仍然显示，可显式撤销；新授权可选择有 user_id 的在职员工，以及飞书部门同步已有准确ID与姓名但尚未入册的负责人。名字相同的员工以部门和 user_id 区分。
- 未入册负责人显示「飞书负责人 · 尚未入册」。候选只读取现有花名册和飞书部门缓存，不实时全量导入人员，也不改变员工入册规则。确认保存时按准确 user_id 调用飞书接口核实，不信任表单传入的姓名。接口仅返回ID时使用该ID对应的部门缓存姓名；离职、冻结、未加入或核实失败则拒绝新增授权。老板等未入册人员获得角色后不会自动进入周报或评分统计，首次实际SSO登录仍由原有流程入册。
- 服务配置中赋予的角色明确标记，只读显示其来源；不能通过撤销名单授权来假装移除配置权限。配置维护方式及现有权限判定不变。

## 保存与兼容

继续使用 `boss_view_members` 和 `scoring360_admin_members` 两项设置，不新增表或迁移原授权。GET返回当前名单、配置授权、当前账号及名单指纹；新页面POST附带 `expectedRevision`。同一服务实例的角色写入串行保护，过期草稿返回409并刷新，避免新页面覆盖另一位管理员刚保存的名单。旧客户端不带指纹的请求保持并发兼容，不能保证阻止其陈旧覆盖；新增人员的候选范围与状态校验对新旧客户端均执行。

授权候选GET `/api/role-authorization/candidates` 仅供管理者读取，独立于 `/api/employees/manage`，不包含账号启用、入职日期、周期或评分任务写入。已有授权保留与撤销不依赖飞书实时可用；本地停用员工不会通过负责人缓存绕过停用状态。

加载任一名单或花名册失败时禁用修改；保存失败保留选择。修改本人授权后刷新当前会话视图。原有服务端鉴权、跨站请求校验及操作日志保留，不改变老板／管理员的管理权限范围。
