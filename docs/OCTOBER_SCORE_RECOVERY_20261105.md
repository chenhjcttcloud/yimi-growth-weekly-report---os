# 十月评分恢复说明

本次为本地修复及验证记录，不代表已推送仓库、部署生产或补跑生产数据。发布须另行取得本次明确授权，并遵守项目 `AGENTS.md`。

## 周报质量分

模型限流会使历史补跑中断；重评未全部成功时，对接接口继续返回未完成状态，历史旧分只作为参考，不能充当本轮最终分。

修复后的 AI 请求使用串行队列和共享冷却时间，遵循 `Retry-After`，区分限流、过载、额度不足和鉴权错误。额度不足或超长等待暂停任务并保留未处理记录；成功记录复用，重启保留任务月份、计数和安全诊断。四模块评分、原文引用校验及自动发布条件保持原规则。

在部署本次修复后，管理员可进入「系统设置 → 飞书与数据集成 → 周报自动收集与 AI 评分」，选择十月，点击“补跑本月未完成评分”。仅使用已保存原文，不重新收集飞书，不发提醒。员工当月全部已提交周报分析成功后，该员工的月度质量分自动发布，产品管理系统即可重新拉取。

## 360 协同分

已有历史周期仍处于未发起草稿、没有真实评分时，不能仅靠重新汇总产生最终分。

新增入口：「评分工作台 → 月度配评 → 选择历史月份 → 开放历史月份补评」。操作前需明确确认；服务端核对周期和版本，只允许开放已有、未发起、关系有效的历史草稿。关闭、已发起或当月已有已发布协同分时拒绝开放。普通历史关系编辑限制继续生效。

开放操作仅更新指定周期状态、发起时间和审计记录，不新增评分关系、不生成分数、不发送消息。评分人可在任务页选择历史月份完成真实互评及负责人／老板评分；仍按现有 30% 管理评分和 70% 同事互评规则自动汇总发布。

任务页按明确月份和周期读取，不退回当前月、不隐式创建周期。切换月份或身份会清除草稿并阻止旧响应覆盖新选择。

## 验证

- 限流专项覆盖 22 个模拟场景，包含共享冷却、最后一次重试、异常等待头、额度暂停和续跑、等待时来源变化及原文证据拒绝。
- 历史补评专项覆盖真实隔离 API 和浏览器流程：确认开放、权限与来源校验、过期版本、跨周期已发布保护、严格按月读取、切月清草稿、迟到响应及重启保留进度。
- 周报补跑、历史分隔离、对接 API、协同工作台、加权月分、周期和时区回归通过；TypeScript 检查与前端构建通过。
- 专项测试使用虚构数据和模拟上游，未向真实飞书发送消息，未补写生产评分。

测试入口：`npm run test:report-rescore`、`npm run test:scoring-history`、`npm run test:product-score-api`。CI 历史补评测试可用 `BUSINESS_TEST_SKIP_BROWSER=true` 仅跳过浏览器部分，隔离 API 验证仍执行。
