# 加载性能优化（2026-10-29）

本轮从公网请求和生产容器只读计时定位到两项主要开销：应用模块在挂载前等待全部历史管理数据；评分概览重复传输周报原始记录和历史结果证据。服务器当时负载较低，主脚本和健康接口响应正常。

本机当前数据的原始响应对比：

| 请求 | 原先 | 优化后 |
| --- | ---: | ---: |
| 评分、设置、个人页启动时的管理数据 | 约 8 MB | 约 2 KB 的周期元数据 |
| 月度评分概览 | 约 19.4 MB | 约 1.9 MB |
| 历史管理分析（首次进入驾驶舱等页面） | 约 8 MB | 约 3.95 MB，按需加载一次 |

前端先呈现加载状态，再恢复导航和身份。驾驶舱、组织趋势、任务闭环、月度会议按页加载历史分析；评分、设置和个人页不依赖全公司历史 AI 数据。评分的完整原始记录和结果依据仅在展开时读取，同一记录折叠重开不重复请求。

后端每次计算复用当月规则；第一次只读取结果是否已发布，概览与个人统计不再读取不会展示的完整证据。没有跨请求缓存，因此下次请求会读取新规则与新记录。默认完整接口保留兼容行为，浏览器通过显式 `view=bootstrap`、`view=client` 和 `view=summary` 请求所需视图。

所有管理视图和新增详情入口继续执行原有管理权限校验，响应使用 `no-store`。普通员工不能通过这些管理接口读取他人的原文或评分过程。历史结果详情携带规则和生成时间，按原版本读取；周报原文携带内容指纹，记录更新时提示刷新，避免概览与证据混用。底层原文、AI 分析、历史评分及依据不因响应瘦身而被改写。

验证由以下脚本覆盖，均使用隔离数据，保留产物，不请求真实飞书或 AI，不发送消息：

- `scripts/test-management-client-data.mjs`：实际客户端映射与原数据等价、启动周期回退、旧格式兼容、权限和完整接口兼容。
- `scripts/test-performance-policy-reads.mjs`：请求内规则复用、下次请求读取新规则、完整结果兼容、个人范围过滤及 SQLite 证据投影。
- `scripts/test-performance-loading.mjs`：统计与分数等价、按页数据请求、加载状态、详情缓存、历史版本、原文指纹、错误响应和权限。
- `node scripts/test-business-regression.mjs`：TypeScript、构建与完整业务回归。CI 可使用 `BUSINESS_TEST_SKIP_BROWSER=true` 单独验证加载测试的 API 部分，报告明确标注未执行浏览器检查。

本轮最终整套回归 42/42 通过。本机真实数据页面复查中，评分页约 0.9 秒呈现，概览接口约 333 ms；这是本机测量，公网耗时仍需正式发布后复测。周报、AI 分析、人工评分和关键配置经内容指纹核对保留；测试期间发生的另一次部门手动同步也已保留。

## 多页面取数优化（本地待发布）

用户反馈多个页面仍等待数据后，复测了运行中的版本。生产内部请求中，个人工作区约 1.26 秒、部门月报约 1.27 秒，评分摘要约 1.98 MB，历史管理数据约 4 MB。服务器 CPU 与内存没有显示持续饱和；主要问题是个人页先计算全公司、部门聚合反复解析大段证据，以及首屏传输未展开的历史明细。

本地继续完成以下调整：

- 个人计算按精确 `user_id` 查询正文与结果，请求内共用周报和规则，保留全部个人历史、滚动分、上期计划及全局轻量日历边界。
- 最新计算哈希相同时跳过写事务；规则或输入变化仍会立即计算，保留 A→B→A 历史版本。
- 评分首屏仅加载概览；打开周报或协作标签后按员工和月份读取明细，原文与历史依据仍按版本展开。隐藏的个人评分任务首次展开才挂载。
- 部门聚合优先读取身份列，一次建立归属索引；旧记录缺少身份列时才解析历史证据。非概览的部门标签不再重复请求月报。
- 管理源文件使用有容量限制的版本缓存；版本包含文件路径、设备、inode、大小以及纳秒 mtime/ctime。每次请求先鉴权再核对源版本，损坏或缺失时失败，不回退旧缓存。JSON 响应支持 Brotli/gzip，继续返回 `no-store` 和 `Vary: Accept-Encoding`，不对动态最终分数做时间缓存。

相同本机 OrbStack、相同真实数据，连续三次接口请求的中位总耗时：

| 接口 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 评分首屏 | 266 ms | 174 ms |
| 个人工作区 | 430 ms | 135 ms |
| 部门月报 | 464 ms | 195 ms |
| 管理历史数据 | 53 ms | 22 ms |

评分首屏从 1,850,603 B 降至 370,885 B（约减少 80%）。管理历史 JSON 保留 3,943,514 B 的完整内容，Brotli 实际传输约 732,253 B；生产先前已有 gzip，因此不能将此原文缩减比例直接当作公网提速比例。上述本机耗时不代表公网体验承诺。

完整业务回归 47/47 通过（45 组测试，加 TypeScript 与构建）。新增测试覆盖个人范围与同名隔离、请求内复用、规则即时生效、冻结源不被修改、压缩解码、热缓存鉴权、坏文件失败关闭、明细按需读取、切人切月旧响应隔离、部门聚合口径不变。测试适用于浅克隆 CI；旧版本完整响应比较仅在旧提交对象可用时补充执行。

本机 5 个主要页面浏览器检查无运行错误。四个业务 API 优化前后投影逐项指纹一致；37 人、342 份真实周报、所有人工评分表、配置和 1,418 条已有自动结果记录均保持不变，SQLite 完整性正常。静态文件和服务源码的旧副本、隔离测试及真实数据测量保留在忽略目录 `outputs/`。本阶段只更新本机容器，未部署生产、未推送仓库。

本轮先在本机验证。生产部署和双仓库推送仍需遵守 `AGENTS.md` 的单次明确授权规则。
