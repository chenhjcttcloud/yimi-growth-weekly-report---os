# 加载性能优化（2026-10-29）

本轮从公网请求和生产容器只读计时定位到两项主要开销：应用模块在挂载前等待全部历史管理数据；评分概览重复传输周报原始记录和历史结果证据。服务器当时负载较低，主脚本和健康接口响应正常。

本机当前数据的原始响应对比：

| 请求 | 原先 | 优化后 |
| --- | ---: | ---: |
| 评分、设置、个人页启动时的管理数据 | 约 8 MB | 约 2 KB 的周期元数据 |
| 月度评分概览 | 约 19.4 MB | 约 1.9 MB |
| 历史管理分析（首次进入驾驶舱等页面） | 约 8 MB | 约 3.95 MB，按需加载一次 |

前端先呈现加载状态，再恢复导航和身份。驾驶舱、组织趋势、任务闭环、月度会议按页加载历史分析；评分、设置和个人页不依赖全公司历史 AI 数据。评分的完整原始记录和结果依据仅在展开时读取，同一记录折叠重开不重复请求。

后端每次计算复用当月规则；第一次只读取结果是否已发布，概览与个人统计不再读取不会展示的完整证据。没有跨请求缓存，因此下次请求会读取新规则与新记录。默认完整接口保留兼容行为，浏览器通过显式 `view=bootstrap`、`view=client` 和 `view=summary` 请求所需视图。

所有管理视图和新增详情入口继续执行原有管理权限校验，响应使用 `no-store`。普通员工不能通过这些管理接口读取他人的原文或评分过程。历史结果详情携带规则和生成时间，按原版本读取；周报原文携带内容指纹，记录更新时提示刷新，避免概览与证据混用。底层原文、AI 分析、历史评分及依据不因响应瘦身而被改写。

验证由以下脚本覆盖，均使用隔离数据，保留产物，不请求真实飞书或 AI，不发送消息：

- `scripts/test-management-client-data.mjs`：实际客户端映射与原数据等价、启动周期回退、旧格式兼容、权限和完整接口兼容。
- `scripts/test-performance-policy-reads.mjs`：请求内规则复用、下次请求读取新规则、完整结果兼容、个人范围过滤及 SQLite 证据投影。
- `scripts/test-performance-loading.mjs`：统计与分数等价、按页数据请求、加载状态、详情缓存、历史版本、原文指纹、错误响应和权限。
- `node scripts/test-business-regression.mjs`：TypeScript、构建与完整业务回归。CI 可使用 `BUSINESS_TEST_SKIP_BROWSER=true` 单独验证加载测试的 API 部分，报告明确标注未执行浏览器检查。

本轮最终整套回归 42/42 通过。本机真实数据页面复查中，评分页约 0.9 秒呈现，概览接口约 333 ms；这是本机测量，公网耗时仍需正式发布后复测。周报、AI 分析、人工评分和关键配置经内容指纹核对保留；测试期间发生的另一次部门手动同步也已保留。
