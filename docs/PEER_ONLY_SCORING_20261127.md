# 同事互评100%：自2026年11月生效

项目所有者于2026-11-27明确要求将360协同评分改为只有同事互评，并确认从2026年11月起生效。

## 计分规则

- 2026-11及以后，全部必要同事互评完成后，以有效评分的算术平均生成月度最终分，按SQLite的`ROUND(AVG(score),1)`保留一位小数。同事互评占100%，不再要求负责人或老板的30%评分。
- 有效0分参与平均；部分完成、未配评、无有效评分不能生成最终分，也不能填为0。老板及本人不参加同事互评；普通部门负责人可以以同事身份参与。
- 2026-10及更早月份继续使用原来的负责人或老板30%＋同事70%。所有已发布结果，包括11月既存的加权或人工历史结果，保留原分、原分项和原证据，不按新规则重算或重标。
- 周报质量月分继续自动生成，及时率独立统计。本次仅调整360协同计分方式。

## 页面、提醒和接口

新月份不再显示30%评分任务、表单、交接要求及催评提醒，不因缺少负责人阻止同事互评发布。旧评分入口用于查看和处理旧月份。老板保留管理查看权限，不转为互评人。

Excel导出和产品管理评分接口沿用实际已发布结果。纯新口径表格只有100%互评字段；混有旧口径历史结果的表格标明历史30%列，新口径行对应字段留空。两类导出仍不包含确认人、确认时间等审核列。产品管理接口的新协同结果来源为`peers_100`；未发布时返回`not_published`和空分数，查询不触发发布。

新月份的负责人提交、老板提交及评分交接接口返回`409 collaboration_peer_only`，不产生新30%评分。旧月份的评分窗口、权限和发布保护继续生效。

## 数据保存与锁定

数据库只追加`monthly_peer_results`和汇总视图`all_collaboration_results`及其保护触发器。旧表、旧视图、历史结果和原始评分均保留。新结果包含`publicationMode: peers_only`、`scoring_rule: peers_100`和`weights: {manager: 0, peers: 100}`。

发布前校验全部必要互评、评分人身份和均分；发布后锁定结果、依据评分、配评关系和周期。新旧结果互斥，不能用另一条写入路径覆盖已发布的结果。异常的旧自评或老板配评记录保留，但不产生新的有效最终分。

本次验证使用合成数据及隔离源码，不连接生产、不发送真实消息。遵守根目录`AGENTS.md`：本地完成后等待本次明确的生产部署和双仓库推送指令；不得删除现有资源、覆盖历史数据或移除旧保护。
