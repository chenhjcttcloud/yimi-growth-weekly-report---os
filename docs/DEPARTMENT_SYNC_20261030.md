# 飞书部门移除同步（本地验证）

当前组织使用飞书同步的有效部门。飞书明确删除的部门在下一次手动同步后，从组织树、部门概览和新的负责人评分对象中移除；原部门 ID、周报、已提交评分和已发布结果保留，历史部门默认折叠、只读展示。

同步先完整读取分页并校验组织树，再核对此前存在但本次未返回的部门。只有同一 `open_department_id` 返回明确删除状态或部门不存在的业务错误，才移出当前组织。权限不足、分页失败、网络错误、身份不匹配或不完整响应不视为删除，界面显示待核查数量。移除状态独立于人工布局配置，避免意外冻结后续名称、层级或负责人同步。

同一飞书部门 ID 重新出现时沿用原系统 ID。不同 ID 重新使用旧部门名称时创建新身份，不继承旧负责人评分；历史名称通过独立显示字段保留。花名册里的旧部门名称不会让已移除部门重新出现在组织树。保留的本地子部门会提升到仍存在的上级或根节点，其他部门仍可正常保存。

新的月度计划排除已移除部门。已经因提交评分而锁定的月度范围保留原分母，未评分的历史部门被标记为待核查，不因部门移除自动完成或发布总分。所有已有评分和发布记录保持原样。

验证结果：

- 完整业务回归 50/50 通过（48 组业务测试，加 TypeScript 和构建）；新增同步、评分范围和浏览器专项，并纳入回归入口及适用的 CI 检查。
- 同步专项包含 23 个隔离场景，覆盖最后一个部门删除、重新出现、同名新身份、权限与分页异常、旧花名册、历史名称和正常布局保存。
- 真实飞书只读预检返回 11 个有效部门、5 个明确删除的旧部门，待核查 0；预检未写数据库或飞书业务数据。
- 本机容器真实同步后，当前组织为 11 个飞书部门加 1 个“公司直属（根部门）”节点，5 个历史部门不再显示在当前组织中；浏览器无运行错误。
- 本机 17 条部门实体记录全部保留；342 份周报、人工评分、在职历史和配置指纹保持不变，原有 1,418 条自动结果保留。通讯录刷新后新增的 12 条自动计算版本不覆盖旧结果。
- 更新前的源码、静态文件和 SQLite 备份已保留并通过完整性检查。测试、截图和验证记录位于忽略目录 `outputs/department-mirror-20261030/` 和 `outputs/tests/`。

本阶段仅更新本机。未部署生产、未推送仓库、未删除业务数据、未发送提醒消息。
