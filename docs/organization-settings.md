# 组织架构设置

入口：**部门管理 → 组织与负责人**，或 **系统设置 → 管理组织**（管理权限用户）。

## 设置部门

- 左侧查看部门树，右侧编辑名称、上级部门、负责人和状态。
- 支持新增一级、同级、子部门，支持两级及更多层级。
- 拖到部门行上变为子部门；拖到行间调整同级顺序；拖到树底部变为一级部门。
- 也可通过上/下移按钮和“上级部门”下拉框调整，无须拖拽。
- 所有修改先暂存，点击“预览并保存”，确认后才写入数据库。离开页面会提示未保存修改。
- 部门不能归到自己或自己的下级。停用前必须移走直属成员和全部下级部门；停用不删除历史评分。

## 跨部门兼任

部门负责人可从系统在职员工中选择。选择其他部门员工时自动勾选“兼任负责人”；如主动取消，保存时会检查本部门成员身份。

例如：海外事业部负责人兼任产品推广负责人。人员仍属于海外事业部，不重复建账号；产品推广的负责人评分独立记录。兼任不自动新增部门成员身份或数据访问权限。

## 与飞书同步的关系

成员归属仍来自飞书。手动修改过的部门，其名称、层级、负责人、顺序及状态以本地设置为准；后续飞书同步仍更新关联来源信息，但不覆盖本地配置。没有手动修改的部门继续跟随飞书同步。

部门改名会保留原名称别名，使旧名称的飞书成员仍归到同一个部门，不自动新增重复部门。

上级部门统计仍按现有规则包含下级成员；此设置不改变员工主部门、任务归属或权限配置。

## 验证

```sh
npm run test:organization
npm run test:organization:ui
```

UI 测试需要本机 Chrome，通过临时 SQLite 数据库运行，不修改正式组织架构。服务重启时自动加载新增数据库表；修改上线需重新构建前端并重启后端。
