# 月度配评工作台

本轮仅在本地实现和验证；没有推送生产或Git仓库，没有删除数据、容器、镜像或文件。

## 入口和操作

- 老板／管理员：**评分工作台 → 月度配评**。
- 本机直达：<http://192.168.200.118:5180/?page=scores&scoreTab=setup>。
- 原来的「系统设置 → 协作评分关系」调整为「月度配评入口」，保留跳转；评分规则、提醒与服务连接继续留在系统设置。
- 员工视角继续显示本人的评分任务，不开放配评界面或API；管理员的员工只读预览也不提供代配评入口。

页面以一张员工关系表展示本月配评，优先排列待配置人员。支持全部／待配置／需处理筛选、部门筛选和姓名／user_id搜索；不再同时铺开两份花名册和重复卡片。

点击员工的「选择评分人／配置」打开侧边编辑。已选人员、搜索框和保存按钮保持可见，名单在面板内部滚动；不展示本人选项。可保存当前员工，或「保存并下一位」继续配置下一位待配置员工。未保存离开有提示，支持键盘操作和手机布局。

负责人／老板的30%关系只读显示，来自组织资料或已锁定的当月责任计划；本工作台只编辑同事互评的70%。负责人缺失时提供相应的组织配置、权限或责任交接入口。

## 沿用、批量和开放

**沿用上月配置**先展示预览，确认后才保存：

- 只为本月尚未配置的适用员工补齐上月有效关系。
- 本月已有配置不覆盖、不追加上月人员；已发布结果保持锁定。
- 自评、已停用人员和不再适用的员工会跳过并展示数量。
- 只复制关系，不复制分数、评价或评分完成状态；新员工保留待配置。

**批量分配**为次级操作：先在表格勾选员工，再在侧边面板选择评分人，明确显示新增关系数后确认追加。自动排除自评和已存在关系，不替用户生成名单。筛选外已选人员会明确提示。

**检查并开放评分**集中显示未配置互评、自评、待评分人员停用／身份缺失、负责人／老板责任缺失等项目。新工作台的开放操作要求所有适用员工通过检查；未来月份预约到月初开放，不提前开放或发送通知。已开放／预约月份提供查看检查，避免重复发起。

配置缺失会直接显示在检查面板，不能把“代码正常”当成“真实名单已经配置完整”。

## 历史和并发保护

- 查看页面、打开侧边面板和预览上月关系，不创建评分周期或关系。
- 首次明确保存关系时才创建草稿周期。
- 取消未评分关系仅将其标记为inactive，保留原行和历史；已提交评分的关系不可取消。
- 已发布员工的关系不可修改；过去月份、关闭月份只供查看。
- 新接口 `/api/scoring360/workbench` 复用现有评分引擎与数据表，不新增另一套计分公式。
- 每次保存携带配置版本；事务内再次核对花名册、评分关系／响应、周期、组织、在职日期及发布状态。其他管理员修改或人员状态变化时，整批拒绝并刷新，避免覆盖尚未看见的变化。
- 每次实际变更追加操作日志；预览无配置写入，保存、复制和开放均不发送消息。
