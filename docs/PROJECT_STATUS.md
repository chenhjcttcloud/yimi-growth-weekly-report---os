# 项目现状

## 当前生产形态

- 前端：React 19 + TypeScript + Vite
- 服务端：Node.js API
- 运行数据：SQLite
- AI：Kimi，采用分块分析、跨周合并和结构化校验
- 企业集成：飞书 SSO、通讯录、汇报、消息、任务和事件回调
- 发布：本地/服务器预处理后生成静态构建，再由服务端提供互动 API

## 已经可用

- 周报按周期导入、回看和历史趋势
- 个人 AI 点评、教练问题、任务候选和跨周闭环判断
- 老板驾驶舱、部门议题、组织趋势和月度会议页面
- 飞书任务创建、互动、追问、通知和活跃审计
- 协同 360 的周期、评分关系、结果和管理配置
- 每 15 分钟自动采集飞书汇报并调用 AI，内容和模型未变时复用有效分析
- 周报质量、提交统计自动生成，节假日最后工作日 20:00 截止，整周放假免交
- 负责人／老板 30%＋同事互评 70%，所有必要评分和评价完成后自动发布
- 月末最后两个工作日提醒、自动工作日日历、授权预警和巡检；提醒需在设置中启用

## 代码库与生产的关系

本仓库是协作开发代码源，不是生产运行目录。

| 层 | 内容 | 是否进入 Git |
|---|---|---|
| 代码层 | React、Node、脚本、数据库 schema、匿名 fixture | 是 |
| 配置模板 | `.env.example`、文档、默认规则 | 是 |
| 生产密钥 | 飞书 App Secret、Kimi Key、SSH 私钥 | 否 |
| 业务数据 | 周报正文、AI 分析、员工身份映射、360 明细 | 否 |
| 运行数据 | SQLite、outbox、访问日志、上传文件 | 否 |
| 发布产物 | `dist/`、服务器备份、release 输出 | 否 |

本机2026-10-28新增全公司通讯录同步：已核验飞书34人、姓名全部补齐；保留1条未返回旧账号，本机共35条。入口为系统设置→员工管理，未登录也可收录。角色和评分关系不自动分配，生产与远端仓库尚未更新。见 [全公司人员同步说明](COMPANY_DIRECTORY_20261028.md)。

1. 生产代码历史此前没有 Git 管理，本次仓库化只建立新的安全基线。
2. 部分前端分析规则仍与静态 JSON 结构耦合，未来应进一步明确“结构定义”和“生产数据”的边界。
3. 周报自动更新使用飞书应用身份，依赖应用权限、可见范围与配置凭据；手动任务等用户身份功能仍可能受用户授权到期影响。
4. SQLite 适合当前低并发规模；并发写入和更高可用需求出现后应迁移到托管数据库。
5. 月度经营分析仍需持续补入财务、ERP、Base 和 Nexus 的事实数据。
