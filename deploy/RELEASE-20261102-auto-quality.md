# 周报内容质量全自动评分发布

用户于 2026-11-02 明确要求本次「推送仓库和生产」。生产目标为 `growth.emie.cn`，同一 `main` 提交同步至 GitHub 和 Gitee。旧版 `reportos.emie.cn` 保持现状。

## 发布范围

- 成果、问题、计划、复盘按固定细则逐项评分，标准化为各 100 分后按所属月份权重加总，默认 30%／25%／25%／20%。
- 保存并展示细项理由、原文引用及位置、缺失证据、模型自评置信度、模型与规则版本。正分引用必须属于对应模块原文；空白模块由程序强制记 0 分。
- 全自动评分和发布，低分、低置信度和异常仅作提示，不设置人工审核、不额外扣分。及时性独立统计。
- 调用或校验失败保持待分析并自动重试，不当成 0 分。旧版月会和部门均分排除待分析记录，报告数量仍完整保留；旧成长页也区分待分析与有效 0 分。
- 旧 AI 分析在重评前保留于历史；自动月分及依据保留版本快照。旧人工发布结果继续保护，协作评分不改口径。

评分细则见 [自动评分说明](../docs/WEEKLY_QUALITY_SCORING_20261102.md)。

## 发布与验证

发布前执行 TypeScript、安全构建、评分专项及完整业务回归。使用已提交源码及对应预构建前端生成哈希清单；先在服务器创建生产备份并独立恢复校验，再用禁网隔离容器预检生产数据副本。

切换使用停止、改名保留旧容器的方式，并新增独立容器运行新镜像；保留冷备份、旧镜像、部署配置和全部既有资源，不执行删除或清理。生产环境、角色、评分关系、提醒开关和反向代理沿用原值，不从开发机覆盖业务数据。

生产若已启用自动收集，新版程序的正常同步会对范围内旧评分重新调用 AI；最近 45 天之外、飞书未返回或默认跳过的停用人员记录不会凭部署自动补评。同内容、模型和新版本一致时复用经过校验的缓存。验证将评分重评与其他业务数据区分，确认原文、旧分析、人工评分、历史发布结果和配置仍保留。发布验收不替员工提交评分，也不主动发送测试提醒。

私密发布清单、生产副本和校验记录保存在忽略目录 `outputs/releases/20261102-auto-quality/`，不提交密钥、真实周报、身份或数据库。
