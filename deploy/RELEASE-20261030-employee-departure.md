# 员工离职状态同步发布

用户于 2026-10-30 明确要求本次「推送生产和仓库」。生产目标为 `growth.emie.cn`，代码同步至 GitHub 与 Gitee 的 `main`；旧版 `reportos.emie.cn` 保持现状。

## 发布内容

- 目录同步按精确飞书 `user_id` 核查缺失员工，明确离职、冻结或未加入时自动停用；状态缺失或查询失败保留待核查。
- 员工页默认展示在职；停用账号和恢复入口独立保留。
- 已停用账号不能登录或继续待评分任务；同事、负责人、老板的评分写入均有状态保护。
- 历史周报、评分、冻结范围和分母保留，不自动恢复已停用人员。

本次没有新增通讯录定时轮询，也不凭目录缺失判定真实员工离职。生效入口和规则见 [员工离职同步说明](../docs/EMPLOYEE_DEPARTURE_SYNC_20261030.md)。

## 验证与部署要求

本地 50 组业务测试及 TypeScript、构建共 52 项检查已通过。隔离测试覆盖目录、SSO、停用后的 API 权限、评分并发保护、提醒过滤、历史保留及桌面/移动端页面。新增离职专项加入 CI。

发布使用同一提交的代码与已验证静态资源；先校验服务器备份恢复，再在无外网的隔离容器使用生产数据副本预检。切换前保留原容器、环境配置、冷备份及所有已有资源；不执行删除、清空或镜像清理。

切换后核验登录模式、开发入口关闭、员工/老板/管理员权限、默认在职筛选与恢复入口、评分与提醒配置、历史数据及 HTTPS。发布验证不发送真实飞书提醒，也不替员工提交评分。私密部署记录、备份信息和运行校验结果保留于 `outputs/releases/20261030-employee-departure`，不进入仓库。
