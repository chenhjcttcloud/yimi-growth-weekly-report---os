# 同事协作评价选填

同事互评的分数仍须填写 0–100 分，协作评价可以留空。零分与空评价可正常提交并参与月度合成；缺失分数、空白、布尔值、数组等不能被转换成零分。工作台、管理进度、自动合成和催评统一按有效分数判断同事任务是否完成。负责人及老板的 30% 评分仍须填写评价，70%／30% 权重、权限和历史锁定规则保留。

## 已验证

TypeScript 与独立目录前端构建通过。10 项隔离专项通过，覆盖同事评分 API、历史补评浏览器流程、加权结果及 API、个人和月末催评、个人数据范围、负责人和老板评分界面、只读规则升级准备。没有向真实员工发送测试消息。

## 既有数据库

仅发布代码不足以升级旧库，须同步更新以下三个触发器的同事评分完成条件：

- `performance_collaboration_complete`
- `weighted_result_validation`
- `person_weighted_result_validation`

使用 `scripts/prepare-peer-comment-policy-upgrade.mjs` 只读核对已安装定义，未知版本停止处理。原始定义、完整数据库和配置另存新备份；在单个事务中核对并替换上述三条规则，其他 schema 对象及评分数据不变。不得通过默认评价、清空表或重建数据库实现选填。用户在已获知这三条规则需同步调整后，针对本次明确要求“推送生产和仓库”；该范围不延续到其他资源或后续发布。
