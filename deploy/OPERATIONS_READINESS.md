# 本轮生产运维准备

生产配置变更必须另获本次明确上线授权。修复代码、生成本文件和样例均不会修改生产或发送飞书消息。

## 容量与备份

2026-10-30 只读检查时系统盘使用率为 90.4%；2026-11-02 复核已约 92.5%（`df` 显示 93%），可用约 2.9 GiB。已有发布备份已通过恢复校验，但每日备份未启用。所有备份持续保留，因此应先扩容或准备独立备份存储，确认容量后再开启每日备份。容量目标、云厂商磁盘操作和费用须由服务器所有者确认；不能通过删除旧容器、镜像、备份或业务数据腾出空间。已盘点出其他系统的历史备份归档机会，但压缩后移除未压缩副本仍需单独的明确删除豁免，不随代码发布执行。

如增加备份盘，挂载到独立目录后使用 `BACKUP_DIR` 指定新备份路径，旧路径与旧备份继续保留。先验证新路径的应用用户写入权限、与业务数据目录不重叠、备份和独立恢复校验成功，再启用每日计划。

## 可审阅的配置

- `operations.production.example.json`：每日北京时间 03:00 备份、磁盘阈值 85%、开启飞书故障通知。将占位符替换成确认后的在职员工 `user_id`，在「系统设置 → 备份与告警」保存。此前已指定的本人通知对象可在页面选「本人」。样例不含真实人员或凭据。
- `weekly-reminders.production.env.example`：沿用现有默认时间，提交截止当天 15:00 提醒；放假时由工作日日历调整到假前最后工作日；周一 10:30 通知周报分析更新。截止规则仍为 20:00。仅发送给系统在职人员，停用人员排除。
- 月末评分提醒沿用现有独立配置：2026-11 起，每月最后两个工作日北京时间 10:00 提醒尚未评分人员。本次不创建或自动复制 11 月评分人名单。

## 只读验收

在应用容器内运行 `node scripts/check-production-readiness.mjs`，只输出容量、备份校验、收件人与提醒开关状态，不写数据库，不创建备份，不调用云 API 或发送消息。

发布验收可加 `--require-ready`；任何必需项未满足时返回状态码 2。源码修复完成与生产配置已生效是两件事，验收记录应分别报告。
