# 产品管理系统月度评分接口与评分历史存储

## 行为

- 新增后端专用 `GET/POST /api/integrations/product-management/monthly-scores`，按同租户飞书 `user_id` 和当前姓名核对。接口只读既有月度质量分及360最终分，不触发分析、发布或历史写入。
- 独立 `PRODUCT_MANAGEMENT_SCORE_API_TOKEN` 默认关闭；启用时使用服务端随机令牌。令牌不进入前端、代码仓库或公开文档。具体请求、响应及空分语义见 [接口文档](../docs/PRODUCT_MANAGEMENT_SCORE_API.md)。
- 自动评分历史只在业务评分依据变化时追加。采集任务时间、重试次数及诊断流水不再生成重复版本；真实状态、原文、评分依据及 A→B→A 变化仍保留。
- 仅对未来较大自动证据使用带SHA256和原始字节数的Brotli JSON封装。摘要字段仍可由SQLite直接投影；完整证据读取透明还原原始JSON字节。既有行、人工评分和加权协同证据均不修改。

## 验证

CI增加接口HTTP、历史稳定性及证据编码测试。测试保留产物，覆盖姓名不符、同名隔离、零分、未完成和重评旧分、独立鉴权、重复读取不写历史、完整证据还原及旧格式兼容。

## 发布与回退

本次发布前生产根盘满导致服务重启。通过降低ext4系统保留块至2%恢复普通用户可用空间，不删除业务数据、历史、备份、镜像或容器。原保留块值及恢复过程保存在私有发布记录；没有新增磁盘容量，仍需持续监控空间并规划扩容。

冷备份在服务器内存文件系统压缩并逐文件恢复校验，随后保存并恢复验证于本地持久存储。运行数据库继续使用原服务器持久磁盘，不改为内存数据库。

旧版镜像不认识新证据封装。启用新写入格式后，回退必须使用本次准备并验证的兼容旧版镜像（仅在旧业务代码上补证据读取器），不能直接重启原始旧容器。发布脚本保留原容器、原镜像及失败容器；回退不恢复覆盖业务数据库，保留已写入的全部评分历史。
